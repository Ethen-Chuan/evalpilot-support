# 售后客服模型运营

更新：2026-10-21。

## 这个功能解决什么问题

将已接入的模型、售后对话评测、失败记录和 Trace 放在同一个工作入口，回答：哪些模型已通过连接测试？这一批客服案例执行得怎样？哪些答复需要核对？问题对应哪一次操作？

这是本机的真实模型离线评测工作台，不是生产流量控制台。没有线上客服、工单和坐席系统的执行凭据时，不宣称完成派单、转人工、灰度或回滚。原独立车辆规则沙盒已从正式界面撤下；旧记录与后端仅保留兼容，不用其数字代表客服模型表现。

## 操作路线

1. 在「模型运营」选择已导入的售后项目。「模型连接」显示工作区共用连接，非项目专属；已配置且通过文字测试不等于持续在线。
2. 没有连接时，点「添加模型」在专用密码窗口输入 Key，另行授权测试。密钥只在服务内存，服务重启后需要重新输入。
3. 点击「新建客服评测」，选择模型、同一批案例与可选裁判，核对发送范围并授权。创建的是实际评测，不会静默使用本地模板代替外部调用。
4. 返回「模型运营」选择本次批次，查看有效答复、执行失败、裁判覆盖、复核提示及各模型耗时与已报告 Tokens。
5. 在「逐条核对与执行追踪」按失败、裁判异常或需核对答复筛选；展开完整答复与裁判理由，再打开原始会话、对应 Trace。筛选与搜索不修改源记录。
6. 从「业务效果与问题归因」进入拦截与填单、质检复核、DSAT。投诉线索与真实低满意度评价分开统计，不由答复关键词自动宣判责任。

## 数据范围与口径

- 本页只读取已有连接元数据与文本评测记录；每 8 秒刷新，不自动调用模型。添加连接、测试和新建评测仍要求独立确认。
- 列表从工作区最近 30 个文本批次筛选当前项目的外部模型批次；历史记录可按编号查询。不将最近列表计为全部历史。不存在或跨项目批次显示错误，不偷偷替换成别的成绩。
- 本批统计排除本地分类器，只包含外部候选。一个案例运行两个模型，计为两份候选执行；裁判请求不重复计为客服答复。
- 返回有效答复：候选执行和输出校验完成的条数 / 本批计划的案例 × 外部候选数。不是问题解决数。
- 执行成功率：有效候选答复数 / 已执行候选数；失败保留在分母，未执行另列。空分母显示未测，不显示 0% 或 100%。
- 模型裁判覆盖：有裁判点评的有效答复 / 有效答复。裁判存在证据不足项时仍算有点评，但显示复核提示；不是人工复核率，也不是质检准确率。
- 答复复核提示：意图与来源标签不同、处理方式与弱行为参考不同、裁判某项低于 3/4 或证据不足。按答复去重计数，只帮助筛查；并非确认的 Bad Case，也不是已经创建的待办工单。
- 耗时 P95：后端按成功候选的执行耗时计算，包含本机处理，不含裁判；不是首字延迟或线上客服 SLA。小样本不能证明模型优劣。
- Tokens：候选和裁判实际报告用量之和，不含连接测试；显示有回报的记录数，部分缺失不能理解为完整用量。没有费率和完整账单时不推算费用。
- 同一连接被用作候选与裁判时提示自评偏差，不能以高分替代独立人工验收。

## 当前不能宣称的能力

没有把评测成功率改名为拦截率；没有把历史回复当作必然正确的知识；没有伪造线上流量、持续健康监控、订单状态、工单解决、满意度或发布结果。

有效转人工拦截、填单准确率与质检准确率继续在结果大盘核对各自的生产凭据、观察窗口和独立人工对照。未取得这些数据时保留缺失状态，不用规则演练的分数代替。

## 实现与验证入口

- 前端：`src/ModelOps.tsx`、`src/modelopsData.ts`、`src/modelops.css`。
- 只读接口：`GET /api/support/lab/state`、`GET /api/support/lab/runs/{id}`；复用现有连接弹窗及评测、知识库、Trace 和业务大盘。
- 新页面不请求旧 `/api/support/modelops/*` 沙盒接口；不会自动触发推理或变更发布状态。
- 构建：`npm run build`；数据口径：`node --test tests/modelops-data.test.ts`；隔离界面测试：`JSDOM_PACKAGE_ROOT=/path/to/jsdom-project node tests/modelops_dom.cjs`。
- 本版验证记录见 `AFTERSALES_MODELOPS_VERIFICATION.md`。旧沙盒验证历史单独保留在 `MODELOPS_VERIFICATION.md`，不作为新版或生产上线的验收证明。
