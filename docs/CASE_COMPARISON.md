# 同一客服案例双模型对话对照

更新：2026年10月20日。

2026年10月23日补充：两侧答复统一展示已记录的裁判意见、三维分数及引用原话；未评审、评审失败和缺证据如实显示。标签诊断默认折叠，只解释模型与历史类别的差异，不用匹配标签判断模型优劣。批次一致性统计已改为诊断性命名。详见 REPLY_QUALITY_REVIEW.md。

## 产品主线

选模型 A/B → 选择客户问题 → 查看共同历史输入 → 确认并运行 → 并排阅读两份下一轮答复及处理记录。

- 默认选具体案例，可只运行1例；批量1–200例通过案例下拉框和展开设置使用。
- 对话视图先展示客户问题，再展示模型原文、识别诉求、处理动作、沙箱结果与 Trace。不得把沙箱草稿当作真实派单、转接或解决。
- 参考人工答复、模型裁判与候选答复独立展示；人工参考和未来回合不进入候选输入。不展示隐藏思维链。
- 可搜索客户问题/案例编号、筛选回复或动作不同/失败未完成、上一例/下一例。两边始终绑定同一caseId。
- 重跑当前案例预填原模型、裁判、caseId和父批次，创建新记录；外部请求必须重新授权。
- 历史记录切换和批次统计默认折叠。单例可完整查看，但不得生成基于不足独立分组的比较区间。

## 实现边界

- 新增本地只读证据接口 `POST /api/support/lab/compare/cases`，不触发模型推理、不修改实验。
- 校验同数据划分、同案例指纹、同协议、同裁判，模型与案例必须属于所选实验；校验快照原文、prefix和reference关系，变更即拒绝冒充原始输入。
- 运行中、失败、取消和中断的记录保留；未执行不是空回复也不是成功。不将失败案例从对话列表悄悄排除。
- `compare` 统计接口保留已完成批次、共同完成案例与独立分组门禁。
- 当前为固定历史时点的下一轮回放，不是动态模拟完整客户多轮会话，也不等于生产业务闭环。
