# 图文案例图库修复记录

日期：2026年10月14日。

## 原因及改动

- 图文来源筛选不应固定为空的真实来源。文本中的图片占位、隔离消息和远程地址不是已通过复核的图像输入，不自动解封客户附件。
- 准备4张带署名的公开VisA示例照片局部：外观说明、针脚偏斜、芯片表面异常、疑似空焊位。题目及政策明确为平台改编，不能冒充真实客户工单、完整VisA基准或线上成果。
- 卡片直接展示PNG缩略图，支持图片与参考标注预览、按数量选定及同源重跑；首次选择有可用图片的来源，后续轮询不覆盖手动选择。缺图记录不进入可选分母，原图片隔离原因和真实/公开/自建数量明确展示。
- 修复「查看拦截大盘」错误滚回准备区：结果锚点仅属于第三步。
- 图片、案例与来源指纹随批次冻结。普通上传继续走原有门禁，裁判/候选连接与费用仍须单独授权。

## 验证

- 30项图文专项测试通过，包括新增公开素材幂等与来源、导入事务回滚、混跑拒绝、图像指纹、防止虚假OCR通过、原候选/裁判图片字节一致及标签不泄露。
- 全量135项中134项通过，唯一失败仍是原有对话日期顺序测试（使用当前首轮时间与固定旧追问时间）；未修改无关测试。前端正式构建通过，既有大包体积警告仍保留。
- 已有服务只读DOM检查覆盖公开图片PNG响应、来源预览、按数量选择和无Key禁用。实际来源数量与模型成绩以当前本机数据库为准，不随本发布文档公开。
- 程序图E04/E09与随机连接测试代码在真实本机DLP中复验通过，记录generated_text_scanned且OCR字符数为空；没有伪称原生OCR恢复。
- 隔离DOM完整交互通过：空库准备4图、真实PNG接口、点击预览及署名、选2例、拒绝超量、真实零条与公开来源切换、两个模型及裁判测试替身完成4条候选结果、Trace及重跑范围。此测试不调用真实供应商。
- 任意用户图片的原生OCR在当前环境报错。仅逐张人工核对的固定公开哈希清单、或者与绘图文本完全一致的程序图片，使用可追溯的确定内容审核并继续执行DLP；其余图片失败关闭。不能声称真实客户新图导入已验收，未修改扫描器返回值或把错误当通过。
- 原图保留；4张派生图无EXIF、无人脸或客户身份字段，裁掉标签色框。自动规则仅返回人工视觉复核提醒；已逐张检查，仍不承诺绝对安全。
- 浏览器图片接口及DOM验证不等于真实窗口布局验收。本轮未完成浏览器自动截图，不声称通过视觉像素验收。

## 复跑

`python -m unittest discover -s tests -p 'test_multimodal.py' -v`

使用新的隔离目录（名称必须以multimodal-browser-开头）启动`tests/multimodal_browser_server.py`，端口4292，然后设置JSDOM_PACKAGE_ROOT与EVAL_BROWSER_BASE运行`tests/multimodal_gallery_dom.cjs`。真实服务只允许EVAL_READONLY=1，测试不写入真实客户记录。
