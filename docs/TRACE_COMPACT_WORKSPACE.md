# 执行记录：从答复到证据

更新：2026-10-22。

## 体验路径

1. 从评测案例打开执行记录。顶部保留本批评测入口；来自结果大盘时返回原来的大盘标签页。
2. 默认查看实际记录的答复、建议动作和标签对照，不再先读 JSON。候选模型名称只取自已记录的模型调用返回，不按页面上的别名猜测。
3. 左侧选择处理步骤，右侧查看该步骤结果。时间条表示起点和持续时间，父步骤包含子步骤，不相加计算总耗时。
4. 要查参数、模型用量、父步骤、错误位置或事件，切换「技术详情」。缺失内容明确提示未记录；缺少 Token 总数时不自行补算。
5. 点击「查看原始完整对话」，可查看来源会话；对话页保留「返回执行记录」，不会丢掉当前批次。
6. 「记录信息与导出」默认折叠，集中提供编号、版本属性、关联事件、脱敏提醒与原有导出入口。

## 精简边界

- 移除重复展示的整条输入输出双面板，用一个步骤与结果工作区代替。
- 少量步骤不增加分类按钮；超过十步才显示步骤分类。长技术内容在桌面结果区域内滚动，不把整页撑高。
- 执行成功不代表答复正确。意图一致是标签对照，行为一致是与规则弱标签对照，不是质检结论或真实操作成功率。
- 未记录客户输入原文的步骤不会为了可读性补造内容；仍可查看原始记录字段。
- 本次只调整前端阅读与导航，不修改历史数据、重新跑模型或清空内存中的连接凭证。

## 验证方法

- `tests/trace-presentation.test.ts`：实际结果抽取、缺失值、时间条边界、父子关系、模型来源、返回路径。
- `tests/trace_detail_dom.cjs`：摘要与技术详情切换、完整对话入口、步骤分类、错误定位、读取失败保护；只使用构造记录，不调用供应商。
- 浏览器检查桌面与窄屏布局、深色模式和技术详情滚动。历史记录只读检查，不发起付费推理。
