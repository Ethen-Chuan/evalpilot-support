# 售后 Agent 训练、指标与模型对比

## 当前交付范围

本轮完成了可运行的本地行为学习基线，不是大语言模型微调，也不是能处理真实订单的生产客服。

| 能力 | 实现状态 | 不能据此宣称 |
| --- | --- | --- |
| 学习人工处理方向 | 在真实脱敏会话上拟合意图分类器与行为分类器，保存两个真实模型文件 | 大语言模型已经学会全部业务知识 |
| 多轮交互试用 | 保留本机试用上下文，执行分类、训练侧检索、沙箱动作和安全模板答复 | 已对接订单、派单、维修或人工坐席 |
| 历史案例重跑 | 冻结历史前缀，重做一个人工客服回合，1–200 个案例、1–4 个版本 | 已模拟完整动态用户、已经验证问题解决 |
| 指标大盘 | 意图、行为、同时匹配率、Macro F1、分场景指标、执行耗时、失败与未完成数量 | 分类匹配率就是业务解决率 |
| 纵向版本对比 | 同厂商同系列的两个版本在同批案例上比较 | 新版本必定更好 |
| 横向模型对比 | 支持登记不同服务商的模型并使用相同批次运行 | 未输入密钥时就有第三方真实成绩 |
| 大模型裁判 | 已实现官方 API 适配、结构与证据校验、独立维度统计 | 已完成外部裁判实测或裁判等同人工标准 |

页面入口：`#overview` 指标大盘，`#playground` 交互试用，`#benchmark` 案例重跑，`#compare` 模型与版本对比，`#models` 模型版本与连接。

## 训练数据与隔离

源码发布版不附带客户项目、训练语料或私有成绩。用户须先导入获授权且完成脱敏检查的会话，再主动训练；实际来源规模、合格案例数、排除原因和分组划分以当前项目界面为准。

每段会话最多提取一个非欢迎语的有效人工回合。标注无效、冲突、缺少合格回复或上下文的记录会单列排除。匿名参与者相同或重复问题归一化完全相同的案例放入同一连通分组，训练、验证与测试分组不交叉。

固定哈希与seed42用于可重复划分。这不是时间外验证或分层随机抽样，也没有消除全部语义近似；小类别可能缺失，必须结合实际分母判断。

### 标签可信度

1. **意图标签**：沿用原整段会话人工标注。模型只能看到某个早期回合前缀，因此它与会话终局意图可能有信息差。
2. **行为标签**：以版本化规则从目标人工回复推导，包含澄清、故障排查、升级人工、维修服务申请、解释答疑。它们是弱标签，尚未逐条人工复核，不是真实工具调用记录。
3. **业务结果**：没有真实解决、满意度、维修完成、订单写入结果标签，因此全部标为不可测。

行为标签包含澄清、解释答疑、故障排查、维修申请及升级人工。类别分布由当前导入数据计算；少数类不足时应优先补标，不只追求总准确率。

### 模型本体

- v1：字符 TF-IDF（2–4 gram，最多 32,000 特征）+ SGD log-loss 分类器。
- v2：字符 TF-IDF（1–4 gram，最多 32,000 特征）+ 类别平衡 LinearSVC。
- 两个版本均只用训练分组拟合特征和模型。验证集只报告指标；本轮没有根据测试结果调参。
- 回答使用版本指纹绑定的安全模板；相似案例只检索训练分组，不把历史维修步骤直接当作正式政策执行。
- 工件保存在本地模型目录。模型加载校验文件指纹；不能从接口上传或反序列化任意模型文件。
- 相同数据和协议再次训练会复用已有版本，不制造虚假的新版本。新的云端微调模型可以登记为新连接版本，但本应用不会启动云端训练。

## 读取本批实际结果

选择已有批次后，核对两个模型各自的已选、完成、失败和待完成数量。平台展示意图匹配率、行为弱标签匹配率、同时匹配率、Macro F1及耗时，不在源码文档预置私有项目成绩。

比较采用共同完成案例，按匿名用户与重复问题分组做配对cluster bootstrap，并显示差异区间、改善、回退、持平及排除数量。区间包含零时，不据此断言总体版本优劣。高准确率与低Macro F1并存可能意味着类别不平衡。

耗时是本机模型加载、分类、检索、沙箱处理及外部调用门禁等埋点范围的墙钟时间，不含裁判、最终出库门禁和结果入库；不是跨硬件标准基准或生产响应SLA。

## 公平比较协议

- 横向：不同版本族，可以是不同公司模型，也可以是不同自有模型系列。
- 纵向：相同版本族的不同版本或不同次运行。名称相同不代表权重相同，模型 ID、工件指纹、提示词版本与实际返回结果必须留档。
- 服务端检查相同 bundle、完整案例指纹、评测协议和裁判指纹。不同批次不能直接排名，应重跑同一批案例。
- 不同顺序的同一组案例具有相同批次指纹。输入来自相同冻结前缀，候选不读取目标人工回复或未来消息。
- 同时匹配率配对差值只使用双方共同完成的案例，单独报告排除数量。失败不算成功，也不隐藏原实验失败数。
- 裁判每个维度有独立有效分母；非同分母的裁判均值仅描述展示，不混进配对胜负。
- 少于两个独立分组拒绝生成比较区间；小样本仍不足以代表总体表现。
- 取消任务会等待已发出的请求结束，保留已经完成的结果，但不发起后续请求。重跑创建新 ID 和父实验关联，不覆盖旧结果。

## 外部模型和裁判接入

在「模型对比 → 新建同批对比」中直接选择模型A/B；点击卡片里的添加按钮可打开「接入模型与版本」弹窗，输入服务商、版本名称、模型系列、候选模型 ID、裁判模型 ID 与 API Key。保存后需另外授权连接测试，通过后点击「完成并选用此模型」。未配置或未测试的模型可见但不能开始运行，并提供修复按钮。

新建对比与已有结果分区，不再把已完成结果下拉框冒充模型选择。新建对比要求两个不同模型、至少2个案例；可按固定规则选取当前独立测试集，或复用指定父批次案例子集。外发确认只绑定当前模型、案例数、来源、裁判；变更后清空勾选。服务端`runs`接受可选`comparisonMode: horizontal|vertical`，同批对比额外校验恰好两个版本与模式，原1–4版本普通评测兼容。版本迭代要求provider和family同时相同；跨厂商同名family不会被归为版本迭代。历史成绩筛选采用同样规则。

不带批次的对比入口默认新建；带`run`的旧链接和`panel=results`链接直接进入已有结果。优先采用URL显式指定的`comparison`，其次采用批次保存的`comparisonMode`；旧批次按实际provider与family推断。URL显式`panel=setup`仍可进入新建。同页地址变化与浏览器后退会更新模式、面板及项目上下文。

连接弹窗实现独立为`src/ModelConnection.tsx`，文字/图文/质检共用；状态轮询不会清空正在输入的Key。保存后的模型身份锁定，再次保存只更新原连接Key，不重复创建版本。候选和裁判只发送到现有固定官方服务地址，不新增任意代理或模型列表假数据。

目前仅允许 OpenAI、Anthropic 与 DeepSeek 官方 HTTPS 地址，不接受任意代理地址，不跟随重定向。模型 ID 由用户填写账号中实际可用的值，不硬编码“最新”模型或价格。

密钥只保存在服务进程内存，不写入 SQLite、日志、Trace、浏览器存储、导出文件或 URL。提交后清空输入框；服务重启或清除连接后失效。用户需要先明确允许不含客户资料的连通性测试，再单独确认真实案例范围、接收服务和潜在费用。

外部候选采用相同任务枚举、历史前缀和业务权限边界，不额外提供目标答案。它与本地分类器架构不同；此处比较端到端沙箱行为，不是隔离单一训练因素的实验。

裁判接收历史前缀、原人工参考、匿名候选答复和沙箱结果，不接收模型品牌名称。三项 0–4 分维度为诉求相关性、下一步可行性、权限与证据边界；证据不足返回 null。理由必须可核查，证据消息 ID 必须存在。只接收完整结束的 JSON，枚举、整数范围、字段集合和证据都会再校验。结构 / 隐私 / 网络失败不生成分数。

适配器按各服务协议请求结构化结果，并执行严格本地schema验证。每次输出上限为4,096 token；不自动重试。所有候选与裁判请求在外发前复扫，返回内容在记录或转发前复扫。失败关闭该路径，不静默降级。

本轮没有用户 API Key，**未进行外部服务的真实连通性或模型质量实测**；仅通过模拟网络响应的契约测试。官方模型服务仍可能因模型权限、上下文限制、网络、JSON 支持或额度失败，这些错误会在界面展示。

协议资料：

- OpenAI 官方 Structured Outputs / JSON mode 文档：`https://developers.openai.com/api/docs/guides/structured-outputs`。本轮已读取，JSON mode 不保证 schema，因此必须本地校验。
- DeepSeek Chat Completion 文档：`https://api-docs.deepseek.com/api/create-chat-completion`。项目已有官方文档缓存；运行前仍需用实际模型连接测试验证可用性。

## 本机 API

全部在 `/api/support/lab/` 下。POST 只接受 `application/json`，沿用本机 Host 与 Origin 校验，没有公网认证或租户隔离。

| 方法与路径 | 作用 |
| --- | --- |
| GET `state` | 训练任务、快照、版本、无密钥的连接状态、实验与聚合指标 |
| POST `train` | `datasetId`、`confirmed:true`，启动本地训练 |
| GET `cases?bundle=…` | 冻结测试案例索引 |
| GET `case/{id}` | 完整原始消息快照、前缀、目标回复与标注 |
| POST `runs` | `bundleId`、`versionIds`、`count` 或 `caseIds`，可附 `parentRunId`、`judgeId`、`consent` |
| GET `runs/{id}` | 逐例结果、Trace 关联、原始选择与聚合指标 |
| GET `runs/{id}/export` | 对完整导出正文重新扫描，通过后返回冻结证据；否则拒绝 |
| POST `cancel` | 请求取消 `runId` 的后续执行 |
| POST `compare` | `sides:[{runId,versionId},{runId,versionId}]`，核验口径后生成配对差值 |
| POST `connections` | 专用内存密钥配置，不用于普通内容输入 |
| POST `connections/test` | 显式确认后执行无客户数据的连接测试 |
| POST `connections/clear` | 清空指定连接的内存密钥 |
| POST `chat` | 本地版本交互试用，`versionId`、`message`、可选 `sessionId` |

## 验证与隐私记录

- 选择和导航单元测试、模型协议测试及隔离交互测试覆盖同批输入、版本模式、冻结案例、外发授权、连接失败、裁判、Trace和历史结果保留；发布验收见RELEASE_CHECKS.md。
- 自动化测试使用显式本地替身，不代表第三方模型的真实质量或在线可用性。
- 原有固定日期排序测试有已知失败，不修改业务排序或数据掩盖失败。
- 数据、完整快照、规则原文、模型工件、截图和内部验证成绩只保留在用户工作区，不进入本发布副本。
- 导出正文必须重新扫描；接口存在不意味着任意批次已获准外发。自动规则未发现明确敏感项不代表绝对安全。

## 进入下一阶段需要什么

若要从“可核验基线”升级为真正会办事的生成式客服，需要正式政策与权限边界、逐步工具调用日志、人工确认的动作标签、可回滚业务沙箱，以及成功 / 失败结果定义。然后才适合做带工具动作的监督微调、全对话用户模拟和生产验收。单靠历史文本推断不能补出这些事实。
