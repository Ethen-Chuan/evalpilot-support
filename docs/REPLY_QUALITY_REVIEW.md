# 答复质量与标签诊断

更新于2026年10月23日。

## 使用路径

1. 在「运行评测」选择批次，阅读「逐例答复与评审」。主列表展示同批案例序号、模型、实际答复摘要、裁判意见和候选执行耗时。序号仅在本批内使用，完整来源编号仍保存在详情中。
2. 搜索答复、模型或原案例编号。筛选全部结果、建议复核、评审未完成、裁判认为基本合理或执行异常；数量来自当前批次实际记录，不是预置成绩。不同模型对同一案例算不同执行结果。
3. 点击「查看对话与结果」，对照当前历史输入和模型实际答复；查看三个裁判维度、评审理由与引用原话。找不到原文时明确提示，不根据编号编造证据。
4. 需要追查分类差异时，展开「标签诊断」。并排查看历史参考类别、模型声明类别、是否一致，以及弱行为标签来源的人工原文。来源意图为整段会话标注，当前前缀可能不足；行为类别由关键词规则推导，未逐条审核，也不是已执行操作。
5. 未评审或评审未完成的记录可点击「选择裁判并重跑」。沿用原模型和原批次案例池，在原池内选择本次案例，明确选定已连接、已测试裁判并确认外发范围与费用后执行。它会重新生成答复并创建新批次，不给旧回复补写分数、不覆盖原记录。
6. 模型对比的两侧也展示同一套裁判意见和证据，标签诊断默认折叠。批次标签统计明确是诊断而非模型质量排名。

## 意见如何产生

沿用已有裁判返回的三个0–4分维度，不修改后端评分提示或历史记录：

| 维度 | 展示名称 | 含义 |
| --- | --- | --- |
| relevance | 答复切题 | 是否回应当前诉求 |
| next_step | 下一步合理 | 建议是否具体、可行 |
| boundary | 权限与证据边界 | 是否诚实说明资料与操作权限限制 |

- 已完成候选回复、没有裁判记录：未评审。裁判失败：评审失败。两者都不算质量不合格。
- 合法裁判记录中任一维度为0–2分：建议复核；即使标签全匹配仍需复核。
- 三项均为3–4分：裁判认为基本合理；即使标签不一致，也不改写该评审。
- 没有低分但有null：证据不足。null不是0分。若既有低分又缺证据，提示建议复核并说明缺证据。
- 缺少维度、分数越界、没有理由或证据编号：评审记录不完整，不给通过状态。
- 候选执行失败或缺少答复：执行异常。已有失败记录不会因残留评分被标成合理。

这些是用于筛选的展示规则，不是经过业务验证的质检合格标准。裁判是辅助意见，需要结合原话和现行政策复核；没有综合总分，不根据标签一致性计算模型胜负。

## 不承诺的能力

- 未新增「转人工是否恰当」独立评分；现有下一步维度不是专门的转接评测。
- 权限与证据边界分数不是完整安全质检或违规检出率。
- 真实拦截率、解决率、满意度仍需要生产坐席、工单和后续结果，不能由这三个分数推算。
- 此次更新不发起模型调用、不启动训练、不重启后端；原数据、历史标签、评分和Trace均保留。

## 验证

单元测试覆盖缺评审、空值、非法分值、缺证据、标签不影响质量判断和动态计数。隔离交互测试覆盖搜索筛选、证据原文、加载失败重试、过期请求、密码与外发授权门禁、既有同例对比。自动化构造记录不是供应商实测。
