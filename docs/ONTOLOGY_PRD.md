# 领域本体工作台：PRD 落地范围

更新：2026-11-06。本页是匿名实现说明，不包含用户原始 PRD、企业政策或真实客户原文。

## 入口与边界

主导航「本体图谱」默认打开 `#ontology?workspace=domain`，同一工作台内有概览、实体与别名、关系图谱、约束规则、版本记录、测试调试六个分区。不是再新增一套侧栏产品。

- 新领域本体存入本机 `ontology-domain.sqlite3`，不覆盖历史客户数据、质检集、旧教学本体或旧命令记录。
- 旧教学图谱 `#ontology?mode=example&view=graph`、旧业务演示、真实数据关系 `#ontology?mode=corpus` 仍保留，并明确区分来源。
- A-100、A-200、A-090、备件及关系都是虚构教学数据，不是任何厂商的故障树。不能用于实际换件、驾驶安全或应急处置。
- 本机维护人确认不等于企业账户认证。服务只能监听环回地址；没有角色权限、组织隔离、双人审批或公网发布能力。
- 启动器同时核对本体能力和服务启动时的实现指纹，避免新页面连到旧后台。旧服务未退出时使用空闲备用端口，不擅自终止用户的其他进程。

## 对照需求

| PRD 能力 | 当前可操作实现 | 边界 |
| --- | --- | --- |
| 统一概念 | 机型、部件、现象、候选根因、备件、动作、等级七类；稳定编号、标准名、别名 | 根因只是可能原因，不自动确诊 |
| 实体维护 | 新增、改名、别名、说明、适用机型、停产与更换属性、启停、删除 | 删除被引用对象、同名或别名歧义会被拒绝 |
| 分类维护 | 分类改名、新增自定义分类、删除无引用的自定义分类 | 七类运行时概念不可删除 |
| 别名批量导入 | UTF-8 CSV / 受限 XLSX；整批扫描、校验、预览后保存 | 单表、两列、最多200行；不接受宏、隐藏内容、公式、二进制对象、外链、损坏文件 |
| 关系维护 | 有向关系、类型限定、机型条件、负向排除、允许和禁止动作 | 同范围矛盾关系不允许保存 |
| 图谱探索 | 默认点线关系网络；保留对象卡片视角；概念聚类、逐级展开、局部1/2层、搜索定位、图层/机型筛选、暂停、拖动缩放、全屏、侧边详情、运行证据高亮 | 两种视角共享数据、选中元素和展开范围；不同版本不混用证据；聚类位置本身不表达业务关系 |
| 规则执行 | 工具白名单、实体与参数校验、机型和关系限制、重大故障升级、停产备件保护 | 使用可执行模板，不执行任意规则脚本；核心红线不可弱化 |
| 版本治理 | 变更前后差异、确认保存、维护人和原因、预览过期、并发版本冲突、回滚产生新版本 | 显示最近50个版本；旧会话使用冻结快照 |
| 多轮对齐 | 最近六轮客户输入；标准词与别名匹配、否定清除、切换设备清空旧对象 | 不是通用 NER；未知词、歧义、未覆盖设备需澄清；不从客服自己的答复提取事实 |
| 知识约束 | 用标准现象和机型过滤结构化示例知识 | 不是向量数据库或生产 RAG，不把图谱本身当作答案 |
| 工具执行 | 本体调试真实调用本地备件目录查询、工单预校验、工程师草稿函数 | 计划是确定性演示；不会创建真实工单、换件或接通真人 |
| Harness 接入 | 客服模拟台可选本体实验模式；冻结领域版本、按实体过滤审核知识、传入结构化上下文、每个工具执行前校验、输出再次验证 | 仍使用原有五个客服工具，不冒充已经把三项领域调试工具暴露给真实模型 |
| 过程追溯 | 调试每步记录输入、输出、时间、排队、开始、完成、失败或拦截；逐事件保存；服务重启保留中断状态 | 不展示模型隐含思维，也不声称审计每行底层执行 |
| 并发治理 | 本体调试单会话单飞、请求幂等、最多8个准入请求、共享2个工具槽、每轮最多3次工具计划、排队超时失败 | 单进程本机限制；不是 Redis 限流，没有生产 RPM / TPM 配额管理 |
| 结果验证 | 发布实体与动作必须来自本轮成功工具；无证据、未确诊成功声明、部分工具失败均不能直接发布 | 客服还必须满足原有审核片段发布机制，保留原提案失败，不用安全兜底洗分 |
| 失败回流 | 失败有持久记录；可据证据修改别名或关系，再跑固定预期，版本可回滚；客服失败保留为复测案例 | 不自动训练模型，也不自动修改专家规则 |
| 分析导出 | 本地运行数、工具拦截、标准故障去重会话、机型×现象、对齐实测 P95、事件 CSV | 不接生产 BI、真实换件统计、经营收益；导出不含原始提问 |

## 匹配分、验收与业务指标不是同一个数

- 标准词精确命中为100，受控别名命中为90；关键实体不足、冲突或低确定表达降到最多45，无命中为0。取有效匹配的最低分，80是机制放行阈值。
- 这是可解释规则分，不是模型正确概率。不能把90分说成九成概率正确。
- 固定验收使用独立登记的13组输入与预期，对比实体、机型、动作拦截数量和输出是否放行。改错别名或规则后，验收可以失败；不自动重写预期以“通过”。
- 真实实体准确率目标仍需用经过专家独立标注的留出集测试，分别报告每类实体的 precision / recall / F1、未知拒识、多轮继承、风险漏拦截及人工复核结果。本次没有将固定演示的通过率写成生产准确率。
- P95 为最近最多500次已完成本地调试中、实际对齐耗时的最近秩分位数，同时显示样本量。不包括网络模型耗时；不证明千级并发或生产延迟目标已经达成。
- 本地故障统计按“会话编号 + 标准现象”去重。一次会话发生多个不同现象可以各计一次，别名不另开一个故障类别。统计包括故障注入场景，不能当成线上事故率。
- 当日按服务本机时区统计，界面显示具体日期与时区。事件导出最多30次，概览统计最多500次，口径不同已标注。

## 五分钟演示

1. 概览说明：本体负责统一概念和限制业务动作，不替代知识库。
2. 实体页搜索“主板”：主控板、控制板都归属一个稳定实体。打开本机维护确认，加一个匿名别名，先看差异，再保存版本。
3. 调试页输入 `A-100 主控板有问题，开机屏幕不亮，需要上门修。`，查看标准实体、机型过滤、真正执行的只读工具与完整记录。
4. 选“黑屏查喇叭”，观察喇叭调用被拦截且没有执行记录；选“违规维修结论”，观察即使前面的工具成功，输出仍可被拦截。
5. 输入缺型号的例子，系统必须询问型号；不要用补造型号来制造成功。重大故障只能升级专业复核，停产备件不能推荐。
6. 在图上点主板、候选根因、机型或别名逐级展开，解释“属于概念”“规范叫法”“可能根因”“适用机型”“禁止方式”的不同含义。
7. 运行固定验收。打开版本记录，预览回滚：产生一个新版本，不删除先前证据。
8. 从概览进入客服模拟台，勾选领域本体实验。先用离线示例验证本体信息进入实际 DeepSeek Harness 工具链；要调真实模型，沿用已测试连接并逐轮授权，不自动产生费用。

## 关系网络与对象卡片：同一份本体的两种视角

入口为 `#ontology?workspace=domain&tab=graph&view=network`，右上可切换「对象卡片」。没有复制旧语料关系来冒充领域本体，也不为填满画布增加业务事实。

- 蓝色双环为概念，绿色实点为标准实体，紫色空心点为别名，菱形为实际执行规则。实体按概念柔性聚类，别名围绕自己的标准实体布局；位置接近不表示互相有关，只有连线才表达关系。
- 「概念与机型」「同义叫法」「业务关系」「约束规则」是可开关的关系层。别名明确指向唯一标准实体；候选线带虚线，禁止/排除线带叉号，允许和禁止的不同机型条件不会叠成同一根线。
- 规则节点及连线由当前版本的可执行模板投影产生。重大等级 → 升级规则 → 现场复核；停产备件规则 → 备件概念，表示对该类对象做查询前检查，不是声称所有备件都已停产。侧栏展示来源、启停、完整名称与条件。点击规则不执行规则，也不虚构本轮触发记录。
- 「关系总览」显示全部当前筛选下的元素。「逐级展开」保留已展开分支，点击节点只补出实际一跳邻居。「局部关系」查看选中元素的一层或两层关系。隐藏名称或缩小画布只减少文字，不删除数据，页脚始终标明当前元素数和总数。
- 机型筛选同时作用于实体、别名及关系；例如 A-200 下不显示仅适用 A-100/A-090 的主板，也不显示 A-100 的允许上门边。通用类定义与规则不会被冒充为该机型已经发生的事件。
- 搜索、侧栏的关系按钮及可用键盘操作的元素目录均可定位。相同节点在网络与卡片间保持选中和展开状态；视图切换不写数据库。暂停后选择节点只更新高亮，不重新启动力导向运动。
- 现有维护、预览确认、版本回滚、工具门禁、审计记录不变。图谱元素和关系数来自当前版本，不写死演示规模。

推荐演示：先看关系总览 → 搜索「主控板」并沿「规范叫法」到主板 → 切换「对象卡片」核对同一实体 → 回到网络选择黑屏 → 切换 A-100/A-200 看处理范围差异 → 选择重大故障规则查看触发对象和要求动作 → 全屏逐级展开。

## 关联分支拖动（2026-11-06）

关系网络默认使用「拖动关联分支」，对象卡片仍保留原有交互。目标是从密集区域带出一组可以解释的关联对象，而不是只留下一个节点和数条长线，也不是递归拖走整张连通图。

- 拖概念：带出直属标准实体及其别名。初始教学版本中，「候选根因」带出固件异常、硬件损坏、连接松动和两个别名，连同概念共6个元素；数量按当前可见数据计算。
- 拖标准实体：带出一跳业务/规则邻居及这些实体的别名，不牵动共享上级概念或仅通过机型范围连接的其他对象。拖机型实体时，允许带出当前显示的适用对象。
- 拖别名：标准实体、同义叫法和直接业务关联一起移动，别名不会孤零零留在远处。联动只取当前图层、机型、探索范围中实际存在的节点与边，不补造或复活隐藏数据。
- 悬停提示本次联动数量；选中后右侧解释范围。拖动中关联节点出现柔和光圈，组内连线和名称优先显示；停稳后仍可核对这组元素与别名。原有跨组连线不会被删除。
- 超过4像素才进入拖动，避免点击误触；主节点跟手，其他成员按帧时间平滑追随。拖动距离达到90像素后充分散开，成员之间保持约30屏幕像素的最小中心距离。松手后完成收敛（最长650毫秒），将本次位置作为新的布局锚点，不再被原聚类中心拉回。
- 工具栏可切换「仅拖当前节点」，按住 Shift 开始拖动可临时使用单点模式。Esc、指针取消、失去捕获或窗口失焦会撤销进行中的拖动并恢复该组位置；页内全屏时 Esc 优先取消拖动。浏览器原生全屏的 Esc 行为仍由浏览器控制。
- 暂停布局只停止后台力导向运动，主动拖动仍有平滑跟随。系统开启减少动态效果时，保留直接操作，缩短跟随并停用附加动效。
- 「重置探索」释放所有拖动锚点并恢复总览。筛选变化保留仍在当前网络组件中的布局与镜头；刷新页面、离开视图不承诺保存人工布局。拖动不调用业务修改接口，不创建本体版本，不修改客户数据、实体、关系或规则。

验收包含：10项拖动范围/排布/插值单测；同一真实 Canvas 组件在1000×680、660×650、360×480及减少动态效果下的分支联动、逐帧追随、放手不回弹、别名可见、标签不重叠、Shift/单点、四种取消、筛选保位和重置测试；领域页面覆盖拖动模式、范围提示和页内全屏 Esc 优先级。原图谱单测和页面流程同时回归。Canvas 栅格与 JSDOM 交互检查不等于真实浏览器整页布局、原生触摸或帧率验收。

本轮验收结果：39项图谱相关单测、领域页面交互、旧图谱交互和业务命令回归通过。8张测试画布 PNG 完成尺寸检查，未报告尺寸错误；已查看8图缩略对比，并复核1000×680及360×480拖动后的原尺寸画布。标签坐标相交由 Canvas 绘制记录额外检查；没有 SVG 整页几何验收，也未据此宣称真实浏览器整页验证完成。测试脚本的纯文本副本及说明文件经自动规则复扫未发现明确敏感项，图片仍需结合可见内容与元数据复核。

## 验证方式

实现包含领域逻辑与注册表测试、隔离的 Harness 集成测试、工具拒绝测试，以及临时数据目录下的页面交互测试。测试不写用户客户数据。

页面自动测试覆盖：六分区、维护开关、重复别名错误、预览后保存、实际识别变化、CSV导入、工具拦截、双视角共享状态、网络曲线绘制、图层/机型筛选、规则定位、逐级展开、全屏退出、画布不可用时目录操作、回滚、旧入口保留。JSDOM 验证交互结构；另用真实 Canvas 2D 实现栅格化同一绘制组件，检查1000/660/360像素画布、有限坐标、选中标签和暂停稳定性。这不等于浏览器完整页面布局验收；自动图形浏览器启动受本机权限限制，不声称已经完成整页截图视觉验收。
