# 客服模拟台：从会话到回归

本机入口：`http://127.0.0.1:4287/#simulator`。它与现有项目集、执行记录和运行评测共用服务，不连接真实订单、资金、派单或人工坐席。

启动器通过轻量健康接口核验客服后台、Rubric 和模型连接协议。依次检查4287、4290、4291，优先复用支持千问的新版；旧端口被占用时使用空闲备用端口，沿用原数据目录，不自动终止进程。请只在启动器给出的新地址操作，不要同时使用旧后台修改数据；旧内存中的密钥不会转移到新进程，需要重新填写。

## 当前演示范围

界面保留「会话模拟、答复对照、复测案例、评分标准」四个入口。已移除经验发布、候选审批、知识回滚、工程配置弹窗和原始协议展示。旧记录保留，但版本不兼容时只可查看，不显示不能执行的复测操作。底层安全检查、调用预算与审计记录没有关闭。

完整面试操作与讲解见 [3分钟面试演示](INTERVIEW_DEMO.md)。

## 五分钟体验

1. 选择「黑屏了，但我已经重启过」，用开场消息开始，或自己输入匿名客户问题。
2. 查看右侧「规则检查」和答复依据；切到「处理过程」，展开客户历史、知识查找和规则读取记录。「客户上下文」能查看事实和本机交接草稿。
3. 点击「对比两种示例答复」。系统用相同客户输入，对照预设问题答复和规范答复；不是两个真实模型的排名。
4. 点击「查看问题答复并保存」，再「保存为复测案例」。在「复测案例」点击「再次测试」；检查通过仍不代表客户问题已经解决。
5. 在「评分标准」查看六维0–4档具体要求，完成有原句引用的人工评分；未评分不补满分。

五个内置场景来自仓库公开示例及自建边界案例：黑屏与已尝试步骤、设备切换与保修、必要转人工、退款承诺、安全升级。它们不是实际客户记录。已导入且通过脱敏的 `lab_case` 也会出现；仅截取已发生的历史用户前缀，不使用未来人工参考答案。

## 两种运行方式

- **离线演示**：实际运行官方 DSH Agent Loop 和本地工具，模型侧为确定性测试适配器。基线故意注入常见错误，用于演示断言如何发现问题，不能用于证明模型能力提升。
- **真实模型（DeepSeek / 通义千问）**：先在弹窗配置对应官方连接。每轮须确认发送会话及检索得到的知识、工具结果至所选供应商，可能产生费用。所选模型提出动作、回复片段编号及引用；服务器核验并渲染审核片段，不直接展示模型自由业务文本。密钥只在本机服务内存；重启后需重新配置。未配置密钥时不自动降级为“真实成功”。

DeepSeek 使用 `@deepseek-ai/dsh-llm-deepseek-api-key` 官方 Messages 适配器；千问通过本项目的 OpenAI 兼容协议适配器接入同一个官方 DSH Agent Loop，并非 DeepSeek 官方提供的千问适配器。两者共用工具、预算、追踪、隐私和发布门禁，只允许已验证官方地址的 POST 请求，禁止重定向、额外地址和自动重试。没有在本仓库中保存密钥，也没有默认自动付费回归。

### 通义千问连接排查

1. 在「会话模拟 → 模型设置」选择「通义千问」。使用百炼普通 API Key，不使用 Coding Plan 专用 Key。只有已配置且通过文字连接测试的模型才进入运行列表。
2. 选择与 Key 一致的地域。北京、新加坡、弗吉尼亚可选共用官方地址；也可粘贴控制台提供的业务空间专属 Base URL。东京必须填写业务空间专属地址。地域和地址变更会清空密钥与授权，防止误发。
3. 业务空间专属地址格式为 `https://{WorkspaceId}.{region}.maas.aliyuncs.com/compatible-mode/v1`。只接受本项目白名单地域的官方域名，不接受代理、任意地址、查询参数或额外路径。可用地址集中定义在 `backend/qwen_regions.json`。
4. 从所选地域与业务空间的控制台复制准确模型 ID，不把产品展示名当模型 ID。保存配置不代表账号或模型已经验证，也不会自动推理。
5. 单独勾选测试授权，再点「测试文字连接」；成功后选择连接，新建会话并逐轮授权运行。测试文字通过不保证该模型支持 Harness 工具调用；客服模拟还要求兼容 Chat Completions 的工具调用能力。

HTTP 400 检查模型与工具参数兼容；401 检查 Key、地域和业务空间；403 检查权限与账户状态；404 检查模型 ID 与地址；429 检查频率、并发和额度。错误仅展示受控诊断，不透传可能包含敏感内容的上游响应。排查时只分享脱敏错误码，不发送 Key。

客服模拟台当前为**文本会话**。千问适配关闭思考输出，以单次非流式上游响应转换为 DSH 事件；不是多模态模拟器。需要评测图片时使用现有图文评测模块，选择视觉模型并另行授权图像读取测试。

## Harness 结构

浏览器 → 输入/授权/隐私门禁 → 冻结任务与知识快照 → 隔离 DSH 进程 → 记忆 → 知识检索 → 政策读取 → 必要状态查询/交接 → 结构化提案 → 发布硬门禁 → 审核片段或安全兜底 → 量化 Rubric → 失败归档。

模型输出必须是 `action / intent / responseCodes / evidenceIds`。政策片段和固定上下文提示都有对应依据。任何未验证的提案被隔离在评测面板，不进入客户回复或下一轮助手历史。离线故障注入基线是明确的测试例外，不允许用于真实模型。

执行事件通过逐行协议持续传回，接收时先隐私复核再写入尝试记录和 Trace。模型步骤记录开始与结束，工具记录开始、完成或拒绝；失败时保留已安全接收的事件，不保存部分模型答案。输入门禁也在 Trace 内。进程收到但尚未传回的最后一小段事件无法保证保存，不能宣称零丢失日志。

固定使用官方 DSH `0.2.2-alpha.2` 核心服务与 Cordis `4.0.6-alpha.1`，不是自定义循环冒充 DSH。该版本仍为实验性版本，升级必须重新验证。没有加载包含终端工具的默认 CLI 配置，也没有加载工程插件、浏览器、文件读写工具或文件上传工具。

| 工具 | 能力 | 不具备的能力 |
| --- | --- | --- |
| `read_case_memory` | 读取当前案例事实与完整历史 | 读取未来答案或其他会话 |
| `search_knowledge` | 按查询匹配并排序已审核、有效的知识别名 | 全网搜索、向量检索、自动采信外部知识 |
| `read_policy` | 读取先前检索命中的有效政策与可选回复片段 | 绕过检索、读取未审核或过期版本 |
| `lookup_service` | 返回明确标记的沙箱状态 | 查询真实账户、保修或退款 |
| `create_handoff_draft` | 生成含问题、历史与事实的本地草稿 | 接通真人、派单或写入企业系统 |

约束：每轮最多 5 次模型调用、6 次工具执行、每次最多 1200 输出 token；DSH 90 秒取消，父进程 95 秒强制结束；会话最多 12 轮，输入每轮1200字符，历史22000字符，总运行载荷46000字符。工具前置条件被代码强制执行。达到上限直接报错，不静默截断或使用部分答案评分。每轮仅一个执行者；修订号避免双击重复提交。

场景、历史和工具结果作为不可信数据。工具无用户指定地址或路径参数。模型密钥经子进程标准输入传递，不写命令行、日志或数据库；子进程清除父环境中的其他凭证。只保留工具输入输出、步骤与用量，不保存隐藏推理。

## 评测口径

发布安全不再依赖“某个危险词没有命中”：服务器核验阶段顺序、片段、引用、当前问题适用性、有效期、动作权限和必要工具证据。旧规则断言仍用于诊断常见错误，但不是安全证明。

Rubric 满分100：知识25、任务20、上下文15、安全20、可执行性15、沟通5。前80分机器核验，后20分必须人工引用实际答复评分。未评保持空值；无红线、全维完成、总分至少85且人工各维至少2档才验收通过。阈值为初版产品设计，尚需实际案例双评校准。详细口径见 `docs/SIMULATOR_RUBRIC.md`。

比较与回归保留不可变案例、知识快照、Rubric、协议及运行实现哈希。两条运行的客户输入相同，但历史客服回复随策略不同，因此不是每步相同上下文的模型实验。旧会话始终使用旧知识。经验验证另建旧版/候选对照，只有审核、原例改善和7项保留检查全部通过才可确认发布，并可回滚。回流只增加审核主题的检索别名，不自动改政策或训练模型。真实模型会话不自动付费重跑。

```sh
.venv/bin/python -m unittest discover -s tests -p 'test_provider_connections.py' -v

```

Harness 测试使用实际 DSH；供应商接口由测试内存传输模拟，验证 DeepSeek Messages 与千问 Chat Completions 格式、地域地址、工具调用关联、允许工具、无重试、步数和工具预算、未知工具拒绝及凭证清理。它不代表真实账号或网络已通过实测。后端测试使用隔离数据库和仅限测试的扫描替身；实际页面操作仍经过真实 DLP 门禁。

自动规则未命中不代表绝对安全。请勿输入真实姓名、联系方式、凭证或内部业务资料；正式部署前还需身份认证、权限、留存与删除策略、企业政策审核，以及真实业务系统隔离和人工验收。本服务仅限本机回环访问。
