# EvalPilot 模型评测平台 · 操作说明

「项目集」是所有业务项目的入口，每张卡片代表一个实际导入的项目。售后客服只是当前已接入的业务，以下步骤以它为例。现有行为基线与转人工拦截指标面向售后；其他业务需要自己的数据、规则与评测标准，不能直接套用售后结论。

本源码发布版首次启动没有客户项目、已训练版本或历史成绩。先按README配置本机扫描器，导入获授权且已脱敏的数据，再学习与评测；如暂时没有业务数据，可先准备公开照片案例浏览界面。本地分类器训练无需API Key，外部模型运行需要另外授权。

适用版本：2026年10月16日。默认本机地址：http://127.0.0.1:4287/ 。如设置PORT，请使用实际启动地址；页内操作链接留在当前服务。服务运行时才能打开。

新增「图文与转人工拦截」：对比不同厂商或同厂商两个版本的视觉模型。这条流程需要你提供支持图像的模型连接；没有密钥时只能准备案例，不生成假分数。下面先给出演示步骤，原文本体验流程继续保留。

## 先体验新的结果大盘

1. 点击左侧「结果大盘」，确认顶部当前项目。现在只有四页：业务指标、质检复核、DSAT归因、意图树。
2. 没有线上结果时，「业务指标」默认打开「正式对话回放」。填写回放数量，点击「学习并回放」，本机从已脱敏语料学习转人工标签、客户意图、匿名产品类别和故障域，并在独立测试分组逐条预测。
3. 点击「质检复核」，查看本机已导入的摘要记录，区分原分、未确认建议和待补。点击「查看与复核」逐维度核实证据；没有把握保留证据不足，不强行补分。没有导入记录时显示空状态。
4. 点击「DSAT归因」，分别查看低分评价和投诉/复核线索。打开「查看与归因」，按来源证据、逐项排查、归因与行动三步操作；没有把握可以保存草稿。没有原始低分评价的线索不混入DSAT统计。
5. 点击「意图树」，从左侧客户诉求沿连接线看到业务分组、具体意图及来源对话数量。下方默认浏览全部含该意图的案例（每页20段），单一意图、多意图与学习资格分别标明；不因学习资格隐藏原始标注案例。分组可折叠，点击案例阅读原话节选，点击「打开完整对话」查看上下文。多意图不等于无效对话，节选也不是模型生成的标准答案。

## 正式对话回放：第一次这样操作

1. 打开「业务指标 → 正式对话回放」。先保持默认50条，点击「学习并回放」；无需密钥，不外发对话，不产生外部模型调用费用。
2. 等待「已完成独立测试」。观察转人工判断准确率和正例召回：准确率高但正例召回低，仍可能漏判转人工。原标注“直接转人工”不等同于现行安全策略中的“必须转人工”。
3. 查看三个基础填单字段的独立环形图和Macro F1。每个环表示一个字段：蓝色正确、橙色不一致、灰色未输出；下方保留条数和分母。点击「核对这个字段」跳到对应案例，避免只看百分比。这里不评手机号、地址或真实工单提交。
4. 在「逐条核对」切换「只看不一致」，对照模型预测与来源标注；点「完整对话」核查标签，点「本次Trace」核查输入截点与执行步骤。
5. 想演示训练变化：保持回放数量相同，分别选择25%「小样本基线」、60%「扩充训练」、100%「全量训练」，每次点击「学习并回放」。训练样本按固定顺序嵌套选取（最少10条），不移动独立测试分组；旧批次保留。上方三张卡、字段环图和逐例输出跟随当前批次；「训练实验」只画真实完成且测试条件一致的批次。仅改下拉框而不运行，不会生成新成绩。
6. 真正的有效拦截、工单填单和质检准确率仍在「线上业务结果」。没有工单结局、72小时重联观察与独立质检金标时不填假数。

学习边界：当前是字符TF-IDF与线性分类器，不是微调大语言模型，也不是多轮自主客服。输入截止首个有效用户提问；后续客服回复只供查证，测试标签不参与推理。来源整段标签可能依赖后续澄清，所以首轮预测不等于最终工单。人工历史回复需按现行政策复核后才能变成知识条目，不自动当作正确知识发布。

同数据、同参数、同测试集重跑，成绩可能相同，这是可复现性，不会为了曲线变化而加随机数。三项字段全部一致率只核对意图、产品类别和故障域，不是完整工单准确率。历史质检复核改判率移到单独的资料区域，只随新增/复核记录变化，不随模型训练变化。

## 实验太多：一分钟整理与找回

1. 在「业务指标 → 正式对话回放」找到「当前实验」，点击右侧「实验记录」。不再使用长下拉框。窗口只显示当前项目的学习回放，每页10条，覆盖全部历史，不只最近30条。
2. 在「近期使用」搜索实验名称、备注或完整/部分编号，也能按运行状态、25%/60%/100%训练量组合筛选。点实验名称打开对应成绩、逐例结果和Trace，三个指标与当前实验一起切换。
3. 点铅笔修改名称，例如「全量训练 · 演示基线」；备注写清本次改动和待验证问题。名称最多80字，备注最多500字，不填客户隐私或密钥，保存时执行本地安全扫描。名称留空可恢复自动命名。
4. 点星标收藏重要实验，演示前从「已收藏」快速打开。未手动命名的旧记录自动显示训练档位、测试量与精确创建时间，不需要逐条迁移。
5. 勾选本页不再常用的实验，点击「归档所选」并确认。运行中的实验不可归档。归档只是收起记录，不删除成绩、原始对话、Trace，也不改变历史曲线。
6. 在「已归档」中可搜索、查看、单条或批量恢复；收藏标记保留，恢复后会重新出现在收藏列表。批量选择仅针对当前页，切换搜索、筛选或页码会清空勾选，避免误整理隐藏记录。

当前已打开的实验被归档后仍留在页面，不自动换一批成绩；再次从无指定实验的入口进入，默认打开最新未归档实验。全部归档时提示先查看/恢复历史，不把旧成绩冒充新实验。原来的实验链接仍可打开已归档结果。多页面同时编辑发生冲突时，取消编辑、刷新记录后再保存，避免覆盖他人的备注。

这里管理的是本地学习回放；文本/图文模型对比继续保留各自评测协议和入口，不混算结果。

## DSAT归因：用一条真实线索走完流程

1. 「结果大盘 → DSAT归因」默认打开有数据的来源。顶部清楚区分低分评价和投诉/复核线索，环图表示当前来源的处理进度；点击图例筛选待办。
2. 打开记录，在「来源与证据」看完整文字对话（保留顺序及角色）或质检摘要。点击「引用第X条 / 引用这段」加入定位证据；可在知识库看全文。缺图片、评价或运行Trace会明确提示，摘要不按编号猜测关联其他会话。
3. 在「逐项排查」核对工程、工具、策略、知识、理解、人工六类原因。每项初始为待核实；选择有证据支持或已排除时必须写可核查依据，未知不能当正常。人工原因只限人工接入后可控行为，先核实规则、权限和交接条件。
4. 「归因与行动」选择一个主因和可选促成因素，写定位依据、反事实检查、动作、负责人和匿名复核人。主因及促成因素必须有逐项支持证据，再勾选人工确认，才能确认或进入修复中。证据不足先保存草稿，不强制猜原因。
5. 完成修复后，从「修复中」填写实际回归编号、范围与结果，转为「人工回归已验收」。每次修改保留版本、历史和归因Trace；归因Trace不是原始Agent运行Trace，也不测量人工调查时间。
6. 已确认主因分布只统计对应来源的已确认记录，一个主因计一次。投诉线索即使确认原因，也不是有低分评价的DSAT。摘要与现行规则存在口径差异时，须核对原评价、时间和交接记录后再判断。

## Trace：先选业务分类，再看耗时

打开「执行追踪」，用上方标签选择模型训练、文本评测、图文评测、客服对话、质检复核、DSAT归因或外部Agent。再组合状态、具体操作和耗时条件，或搜索批次编号。卡片数量与列表均随筛选更新；分类标签数量基于其他筛选条件下的匹配记录，不只数当前页。

耗时是本次埋点范围内的起止时间差：1,000ms=1秒。约25ms的本机分类器单例预测不是历史客服会话时长。训练任务可能包含回放；人工复核/归因保存Trace不包含人的阅读思考时间；外部Agent为上报方声明。详情会解释对应计时范围，父子步骤不能相加。

数据隔离：同一匿名用户和重复首问归入同组，组间分开训练、验证与测试。新划分覆盖含转人工标注但缺少意图标注的对话；它与旧行为Agent的测试集不同，不能直接拿两批准确率排名。路由测试只有一种标签时不展示准确率，训练标签只有一种时不硬造预测。

## 质检复核比率：看分母，再看记录

1. 在「业务指标」或「质检复核」查看「质检复核 · 比例与证据」。整环代表全部导入摘要，图例同时显示条数和占全部记录的比例；点击颜色或图例可查看对应来源记录。
2. 「可核对样本的改判率」= 明确改判条数 ÷（明确改判 + 明确维持条数）。仅统计可明确核对的记录；不可将分母改为全部摘要，也不能外推全部质检效果。
3. 「可核对覆盖率」= 有明确原判及可对照复核结论的条数 ÷ 全部导入摘要。待核实和冲突记录单列，不当作维持原判。
4. 「本平台人工复核完成率」= 在本平台已保存人工复核的记录数 ÷ 全部导入摘要。只统计本平台新确认的记录，不否定来源文件已有人工复核。保存后条数与比率自动更新。
5. 来源的「已通过 / 不通过 / 部分通过」可能表示申诉流程状态，未确认字段含义之前，不直接推定最终合格或不合格。原判为不合格却标记「降级为不合格」的记录也不算改判。同规则版本的本平台明确人工结论优先用于对照，来源原文不覆盖。

百分比在图中保留一位小数，分子分母始终展示。没有可核对样本时显示「暂无」，不把未知写成0%。这些是摘要复核比率，不是独立全会话质检准确率。

## 可选：用大模型重跑质检摘要

1. 在「质检复核」勾选需要的记录，点击「裁判重跑」。只重跑所选范围，可指定1–50条；数量不能超过所选记录。
2. 点击「添加连接 / 输入API Key」，在密码框填密钥并保存到本机内存，再单独授权测试文字连接。关闭配置弹窗后，选择已经测试的连接。
3. 核对本次外发材料和费用并确认。只发送脱敏机审摘录、渠道及完整规则，不发送原分、建议分或人工复核意见。每条记录调用一次，不自动重试。
4. 查看下方「裁判重跑记录」，展开逐条结果和Trace。模型返回证据不足时没有总分；失败不会补成满分。可停止后续调用，已在途的调用仍可能完成并计费。
5. 裁判输出仅为复核建议。要确认分数，仍需在「查看与复核」逐维度填写依据和匿名复核人；历史分数、裁判输出和每次人工复核均保留。

沿用规则：100分起评，低于90分不合格；7个一级维度、21个子项，同一级只扣一次；观察项0分。只评人工接入后的服务，热线不套在线差评12小时留言规则。规则原文可从「查看沿用规则」展开。

只有摘要而没有完整录音、会话或运行日志时，不能据此算独立质检准确率；人工确认摘要也不会自动成为全会话金标。

## 可选：接入线上结果与闭环归因

1. 点击大盘右上角「接入业务结果」，展开字段模板，准备已脱敏的JSON。每条对应一通完整会话，明确production或sandbox，最多100条。
2. 授权校验入库后，production结果进入项目指标；sandbox只保存，不计入线上成绩。相同匿名编号重复导入不重复计数，冲突不覆盖。
3. 有效拦截分母只包括结束后观察满72小时、且解决/重联/转人工/必转/安全字段均明确的生产会话；分子还需确认解决且其余四项为false。尚未成熟和字段不全数量单独披露。
4. 填单需人工确认的expected与模型predicted字段；漏填计错，整单全部一致率还检查多余字段。质检需同规则版本、独立预测及人工金标的合格/不合格对照，不接收建议分当金标。
5. 1–2分真实评价自动进入「DSAT归因」待办，3分中立，4–5分满意；无评价不按满意处理。平台保存的是来源声明，不会凭情绪词生成评价。
6. 归因时选择一个主因，可补充其他促成因素；填写证据、反事实检查、负责人和改进动作。先进入「修复中」，提交实际回归证据后才可「人工回归已验收」。状态变化不会冒充系统自动验收。

全链路数据覆盖是各阶段会话计数，不是逐步转化率。平台目前接收结果快照，不会自动连接你的工单、坐席或CRM系统；可先用sandbox校验接口，再导入观察完整的生产结果。

## 可选：图文演示，选案例 → 选模型 → 看拦截效果

1. 点击「模型对比」顶部的「图文与转人工拦截」。同一页面提供案例选择、运行、大盘与逐例证据。
2. 点击「添加真实图文案例」，选择已脱敏的售后图片副本。系统在本机检查文字、去除元数据；随后仍需人工复核人脸、手机号、二维码、工牌、地址、设备编号、公司和客户信息。填写问题或截止当前的完整对话、业务政策、视觉事实、参考答复和标准路由，确认保存。此时不外发图片。
3. 演示可选「准备公开照片案例」：24例使用20张官方VisA板卡照片和4张已审核局部图，保留来源署名；可按外观、部件定位、信息不足、通电安全、维修边界等分类，按数量选择、翻页、预览。新增照片定向来自四类板卡的Normal外观样本，不代表24种独立故障或完整基准。中文问题与政策由平台改编，不是客户工单。也可选4个自建E04/E09校验案例，它们只有2张不同图片；三种来源分别评测。
4. 点击「添加模型 / 输入 Key」。横向对比：分别创建 OpenAI 与 Anthropic 连接；纵向对比：同一厂商创建两个不同模型 ID 的连接。填写账号实际可用且支持看图的 ID，不能只改显示名称。密钥只在密码框输入，仅保存到本机服务内存。
5. 在弹窗另行授权测试，点击「测试图像读取」。它发送本地绘制的随机码图片，候选和不同的裁判模型最多各调用一次，可能计费。真正读对才标记通过；文字连接成功不能证明能看图。
6. 选择两个测试通过的版本；选择同一个独立裁判，或保持人工评审。填写数量后点击「按数量选择」，也可逐项勾选。核对已选数量、发送目的地、裁判、最大调用次数和费用，确认有权外发后点击「开始同批图文评测」。每批 1–50 例，每例 2 次候选调用；带裁判最多 4 次，不自动重试。
7. 在下方「拦截效果大盘」看两列实际结果。选择一条案例，展示同一图片、问题、两个客服回复、路由决策与评审理由。点击「查看 Trace」查看调用、图片指纹、模拟路由与评审。没有真实退款、派单或人工转接操作。
8. 裁判不是最终真相。点击「人工复核」，检查看图、答复与解决三项，填写依据保存，大盘随即更新；人工意见优先，历史修改和原裁判结果保留。没接裁判时可用这一步评分。
9. 点击「选数量重跑本批」，回到顶部修改数量，再点击「按数量选择」，确认授权后重跑。原批次保留；子集内两个模型可以比较，但不能直接与完整旧批次排名。
10. 在底部「横向 / 纵向结果对比」选择基线与候选，点击「计算配对差异」。只允许相同案例、图片、政策、协议和裁判条件；展示共同完成且已评审数量，以及按图片分组的差异区间。小样本或区间跨零不足以认定版本更好。

## 拦截指标：演示时这样解释

- 有效拦截率（离线评审）= 标注可自助解决、模型直接答复，且视觉正确、答复符合政策、完整解决需求三项都通过的案例数 ÷ 本批全部选定案例数。失败、未执行、未评、路由未知、澄清和必要转人工均不算成功。全部未评显示「未测」。
- 必须转人工却被拦截率 = 必须转人工、模型却直接答复或继续澄清的案例数 ÷ 所有必须转人工案例数。越低越好；必须转人工未完成数单列，因此零误拦截不等于安全通过。
- 必要转人工召回 = 正确建议转人工数 ÷ 所有必须转人工案例数。安全风险、权限不足、明确人工诉求应当升级，不能为了提高拦截率阻止转人工。
- 视觉正确率仅计算已作明确视觉判断的记录，分母同时展示。评审覆盖率识别未测数据；必须一起解释，不能只挑高分指标。
- 未建议转人工率包含澄清，是代理指标，不代表客户问题解决，不能叫真实业务拦截率。
- 线上真实拦截率目前「未测」。落地需要会话级业务完成或用户确认、实际转人工事件，以及事先约定观察窗口内的重复联系。沉默、放弃和仍未解决不应计成功。要论证 Agent 带来的提升，还需线上随机分流或可靠基线；离线分差不是因果结论。

讲解示例：若 10 个案例中 6 个被确认无需人工且正确解决，有效拦截率为 60%；另外必须转人工的案例应安全升级。这是假设算式，不是当前平台的实测成绩。

当前边界：单轮文字 + 单张图片，不支持音频 / 视频，不是闭环多轮用户模拟。原数据集中被隔离的图片不会自动解封、下载或用占位文本冒充识图。两个版本使用相同输入字节，但服务商内部图像处理、模型别名更新和裁判偏差仍可能影响结论；正式测试应使用可固定的版本 ID，并人工抽查。

## 图片为空时：现在这样体验

1. 图文页面会优先打开已有可用图片的来源。发布包提供24张可主动导入的公开图片素材，卡片直接显示实图；点击图片可以查看原图、标准答复及署名。若是首次安装的空数据库，点击「准备公开照片案例」并确认，即可在本机导入，不会调用模型。
2. 公开照片来自VisA官方示例，问题和售后政策是平台改编，不是您的真实工单；低分辨率局部图也不代表完整VisA基准。自建E04/E09校验图、公开照片、真实售后分为三类，不能混跑、混算成绩。
3. 在「选择数量」填2，点击「按数量选择」，可见2张卡片被勾选。接着选两个已通过图像读取测试的模型及同一裁判，核对外发范围并确认开始。没有API Key时仍可浏览图片和标准答案，但不能产生模型成绩。
4. 如果「真实售后」来源为空，页面解释缺失原因，并提供导入图片和查看公开照片的入口。被隔离的图片消息不是已复核图片，不能用占位文字评测视觉能力。
5. 要评自己的业务，请导入已脱敏的图片副本，按已有流程复核图片与标准答案。不会因为准备公开照片而恢复原私有附件或自动上传客户资料。

## 先记住这三件事

- 平台测试的是：给模型一段真实历史上下文，看它下一轮如何回答、建议如何处理；不是让它完成整段售后业务。
- 完成本地训练后会生成两个版本，都是行为分类器加安全模板，不是微调后的大语言模型。不要用它们的聊天流畅度代表外部大模型效果。
- 所有业务动作都是模拟。不会真实退款、派单、维修或接通人工；匹配率不是解决率或客户满意度。

## 3. 看本批结果，不急着看总分

1. 在评测页面点击「查看本批大盘」。平台会保留刚才的批次。
2. 在「业务指标」的「模型对比 · 同一批真实案例」确认参考批次。图表现在位于逐例长表之前，先看两个模型的准确率及正确条数，再看「本批累计表现」。

## 4. 对照两个版本，再看一个问题案例

模型对比现在分成两个入口：**新建同批对比**选择要运行的模型，**查看已有结果**选择已经完成的成绩。不要把历史批次下拉框当成模型选择器。

### 第一次选择模型并运行

1. 打开左侧「模型对比 → 文本行为评测 → 新建同批对比」。在模型 A / 模型 B 两张卡片中选择基线和候选。下拉框显示本机版本及已登记的外部模型，没有登记的服务不会假装可用。
2. 先体验本地流程：点「先用两个本地版本体验」，自动选中两个版本并切换到「版本迭代对比」，无需 Key。
3. 对比其他厂商：在相应卡片点「添加基线模型」或「添加候选模型」，或点右上「添加模型 / 输入 Key」。选择支持的官方服务，填显示名、模型系列及账号实际可用的模型 ID，在密码框填 Key，确认后保存。
4. 保存不等于可运行。勾选仅发送自建测试材料的授权，点「测试文字连接」，通过后点「完成并选用此模型」，回到原卡片自动选中。没有 Key 或测试失败会显示原因和「输入 Key / 连接」「测试连接」按钮。服务重启后需要重新连接；不要把 Key 发在聊天或备注里。
5. 跨厂商或不同系列用「跨模型对比」；同厂商同系列的两个模型版本用「版本迭代对比」。新建第二版时沿用系列名称。不同厂商即使恰好填同一个系列名，也按跨模型处理。两边不能选择同一条模型记录。
6. 选测试案例来源与数量（2–200例且不超过实际案例数）。默认使用当前项目独立测试集；也可复用已有批次的案例。两个模型都会重新跑同一份案例，原成绩保留。只选旧批次子集时，不与完整旧批次直接排名。
7. 裁判可先跳过，也可展开「模型裁判」选一个已测试连接，两边统一使用。确认数据发送目的地、调用次数和费用后，点击「开始同批对比」。修改模型、数量、来源或裁判会清空外发勾选，需重新确认。仅本地运行不需要外发授权。
8. 页面转到本批执行进度，完成后点「查看对比结果」。模型响应失败、隐私门禁失败或独立分组不足会明确提示，不伪造可比成绩。每个案例保留实际输入、输出和Trace。真实外部模型效果必须由你授权连接后实跑，本地测试替身不进入业务项目。

### 查看已经跑过的结果

1. 最直接的方式：在「运行评测」选中批次，点「对比本批版本」，自动进入该批已有结果，并识别跨模型或版本迭代方式。原来保存的批次链接同样适用。也可以从「模型对比」切到「查看已有结果」；本机两个已有版本用「版本迭代对比」。
2. 确认「基线结果」为 v1、「候选结果」为 v2，点击「查看对比结果」。系统只提供案例、数据划分、协议和裁判一致的候选结果。没有候选时点「选择模型并新建对比」，不必再去隐藏菜单找连接入口。
3. 看改善、回退与持平的案例数。如果提示「本批差异尚不确定」，不要把轻微分差当成确定提升。
4. 在「逐例对照」点击「基线」或「候选」，阅读模型实际输入、生成答复和历史人工下一轮原文。
5. 想看整段历史，点击「打开整段原始对话」；想查运行过程，点击「查看执行步骤」，再点「返回本批评测」继续。

执行记录 Trace 只记录本次实际发生的模型判断、检索、模拟动作和评测步骤。历史对话没有的操作记录不会补造，也不包含模型隐藏思维链。

## 可选：让大模型回答，或请大模型当裁判

首次体验到此已完成，下面只在你需要外部模型时操作。接入现有模型不等于训练或微调模型。

1. 展开左侧「更多工具」→「模型连接」→「添加模型连接」。
2. 选择支持的官方服务，填版本显示名称、候选模型名称。模型名称需填写你账号中实际可用的模型 ID。
3. 「模型系列」表示同一产品系列。同厂商同系列的两个版本用于版本迭代对比；不同厂商即使系列名相同也按跨模型处理。裁判模型名称留空时使用候选模型。
4. 只在弹窗的「API Key」密码框输入密钥，不要发到聊天、截图或说明书。确认用途后点击「保存内存配置」。
5. 另行勾选连接测试授权，点击「测试文字连接」，确认测试通过。该测试不含客户信息，但可能产生少量费用；图文评测另需通过「测试图像读取」。
6. 返回「运行评测」→「新建评测」。要测试大模型答复，就勾选它的版本；只想让它评分，则保留本地版本，并展开「模型裁判」选取已测试的连接。
7. 核对发送目的地、数据范围、最大调用次数和潜在费用；有权外发这批数据时才勾选授权。先跑少量案例，再决定是否扩大。

外部候选会收到历史上下文；裁判还会收到历史人工参考和候选答复。外发前仍有脱敏门禁，不通过就不能发送。密钥只存在本地服务内存，服务重启或点击「清除密钥」后需重新填写。

裁判按相关性、下一步可行性、权限与证据边界分别给 0–4 分；证据不足可记未测。它不是人工最终判决，同一模型兼任候选和裁判可能有自评偏差。

要做横向对比，在一次评测里同时选择不同系列的模型。运行完成后进入「模型对比」→「跨模型对比」。尚无实际运行结果时不会显示排名。

## 遇到问题时

- 没有案例或版本：源码版默认空库，先确认已在当前服务导入获授权数据并完成本地训练。已有工作区不要重复导入客户文件。
- 没有结果：先点击「新建评测」实际运行；训练成功不等于评测完成。
- 结果看起来换了：核对「评测批次」。当前标签页记住你选的批次；首次没有选择时优先展示最近记录中已完成、案例数最多的一批。更早的记录可用原批次链接打开。
- 没有可比候选：在同一批评测里勾选两个版本。案例或裁判不同的批次不能直接比较；小批次独立分组太少时也会拒绝对比。
- 有失败或未测：打开对应记录查看原因。缺失、失败的裁判评分不是零分，也不算通过；不要为了让数字好看而隐藏失败。
- 裁判或模型连接失败：核对模型名称、密钥权限和服务状态；不会伪造结果。正式外部调用需你提供可用连接，本指南不代表外部模型已实测成功。
- 导出被拦截：「记录详情与导出」包含完整消息，需再次通过扫描。当前已有批次可能无法通过全量导出检查；不要绕过门禁，先人工复核再处理。
- 数据出现疑似敏感内容：停止对外展示并复核。自动规则未发现明确敏感项不代表绝对安全；本指南不含客户原文，不可代替对整个工作区的外发审核。
- 页面打不开：在项目目录按README安装依赖、构建并运行npm start，使用服务实际输出的本机地址。发布版不附带个人电脑的启动快捷方式。不要把本机服务直接开放公网；当前没有多用户鉴权和权限隔离。
