# 个人私有项目集：保存与恢复

## 存放边界

公开源码仓库不包含客户数据。独立的个人私有仓库只保存已经全量脱敏、复扫通过的文本包；原件、图片视频、脱敏密钥、映射、数据库和审计明细留在本机。私有不替代处理授权或人工复核，也不限制 GitHub 平台本身和账户已授权应用的访问能力。

数据仓库必须是当前登录账户拥有的非公开个人仓库，不能是 fork。仅保留拥有者，不邀请协作者，不添加部署密钥，不启用 Pages 或 Actions。恢复工具在联网下载前检查这些条件；不能列出权限也会停止。该检查不是持续监控，账户授权应用仍需拥有者在 GitHub 设置中单独检查。

## 首次登记

先在受控环境创建和检查私有仓库，上传经过复扫的 `_redacted.jsonl` 和 `manifest.json`。文件路径为 `packages/<dataset-id>/`，此目录不放脚本或其他文件。不要把真实语料添加到公开源码仓库，不能强制添加被忽略的文件。

准备 GitHub CLI、本机扫描器及项目 Python 环境。用自己的账户完成 `gh auth login`，不要把访问令牌写进源码、登记文件或聊天。通过受信渠道取得数据提交的完整版本号及已复核清单的 SHA-256 指纹。

```sh
.venv/bin/python scripts/private_dataset.py register \
  --repository OWNER/PRIVATE_REPOSITORY \
  --dataset-id DATASET_ID \
  --commit FULL_40_CHARACTER_COMMIT \
  --manifest-sha256 FULL_64_CHARACTER_SHA256
```

登记完成即恢复到当前本机项目集。默认登记文件为源码仓库**同级** `.evalpilot-local-data/registry.json`，不在源码目录内；也可通过 `EVAL_PRIVATE_CORPUS_CONFIG` 或脚本的 `--config /absolute/private/path/registry.json` 显式指定。服务启动时若使用非默认位置，也要设置同一个环境变量。登记文件、下载缓存、备份和脱敏密钥需私下保存，不能上传到公开仓库。

## 日常更新与恢复

- 更新应用源码不会更换数据包。服务启动检查登记文件：本机已经完整导入时直接保留，既不联网也不重复导入。
- 数据缺失时，优先使用本机固定版本缓存；无缓存才凭自己的 GitHub 登录取回**指定提交**的文件，不跟随 `main` 自动更新，不执行数据仓库中的代码。
- 下载后检查清单指纹、每个文件的指纹、数据结构、完整数量并全量扫描；任一失败均停止导入。导入前创建数据库备份，写入使用事务。
- 相同记录不重复增加，已有内容发生冲突则拒绝覆盖。新数据版本必须单独规划迁移，不能随意改登记文件来覆盖人工标注。
- 断网时已经导入的数据仍可使用；缺失数据恢复失败会明确提示，不用演示数据冒充恢复成功。
- 服务正在运行时可手动恢复，然后刷新「项目集」。此操作不会重启服务或改变正在进行的评测。

```sh
.venv/bin/python scripts/private_dataset.py restore
.venv/bin/python scripts/private_dataset.py check-access
```

换电脑或在新目录克隆源码时，需要私下迁移登记文件或重新登记，并重新登录 GitHub、配置扫描器。单独下载公开源码不会得到私人数据。若所有本机文件丢失，仓库拥有者仍可从自己的私有仓库取得版本和清单，再复核登记；没有账户权限的人无法由公开源码恢复数据。

备份恢复的是脱敏历史对话和原始标注，不是训练好的模型、后续人工修改、运行记录、密钥或完整业务数据库。后者需要另做本机备份。此流程不自动训练、不自动调用模型、不把历史客服答复发布成已审核知识，也不会将本机新增数据自动上传。

## 质检表的独立保存与恢复

热线与在线质检作为独立 `quality_inspection` 数据包，和客服历史对话存放在同一个本人私有仓库的不同版本目录。不上传原始 Excel；只允许完整扫描通过的 `_redacted.jsonl` 与清单。原始文件保持不变，脱敏密钥、身份映射、图片、超链接和元数据不上传。

页面入口为“项目集 → 质检数据集”。数据名称、记录数及正文覆盖以当前用户实际导入内容为准，公开版不附带任何客户项目。未附带录音或正文的记录不能回放或独立验证人工分数；高风险正文需要隔离，缺失证据不补造。

两种模板保留源表人工总分、合格/不合格/未填标注、七项问题标签和质检意见。七项为流程规范、问题解决、风险提醒、服务态度、服务闭环、礼貌用语、主动服务；它们是**源表问题标签，不是七个数字维度得分**，也不是模拟台的六维 Rubric。合格标注未填时不根据总分补算。零分、未填和不合格是不同值。

导入写入 `quality_corpus` / `quality_record`，不混入意图分类训练、对话知识库或本体节点；没有自动模型评分、伪造 Trace 或由总分推导合格阈值。启动通过同一份私有登记文件核验全部记录的内容指纹，完整数据保留，缺失记录从固定版本恢复；内容冲突则停止，重复启动不重复增加记录。源表修改后需要复核、发布新的数据版本，不自动跟随远端主分支，更不向公开源码仓库上传。

准备命令 `scripts/prepare_quality_datasets.py` 将两种模板转换为规范包；`scripts/publish_quality_datasets.py --confirmed-reviewed` 在权限门禁后仅发布已审查文件，并下载核对字节一致性；最后通过上述登记命令固定版本。换目录、换电脑依然需要迁移私有登记与登录，不保证单靠公开代码可恢复私人数据。

## 恢复测试

`tests/test_private_corpus.py` 覆盖权限收敛、固定版本、指纹篡改、路径限制、符号链接、额外文件、重复恢复、离线保留及失败提示。外部模型调用不在此流程中。

本机运行时可执行：

```sh
.venv/bin/python -m unittest discover -s tests -p test_private_corpus.py -v
.venv/bin/python -m unittest discover -s tests -p test_quality_corpus.py -v
EVAL_QUALITY_BASE=http://127.0.0.1:4294 JSDOM_PACKAGE_ROOT=/absolute/path/to/jsdom-package-root node tests/quality_dom.cjs
```

自动规则未发现明确敏感项不等于绝对安全。对外演示前还需人工复核隐含身份、自由文本标签、业务数值和上下文组合；隔离正文和未导入的媒体不得被当作仍然可评测的证据。

恢复完成后应核对内容指纹；再次恢复已有记录应返回 `already_present`，不增加重复记录。复现测试应使用隔离的人工夹具，不要求访问原作者的私有仓库。覆盖项目入口、七项问题标签、缺失证据、分页、错误重试和取消过期详情；DOM 检查不代表浏览器视觉验收。
