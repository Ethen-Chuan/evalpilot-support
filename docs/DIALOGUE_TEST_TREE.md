# 多轮对话测试树：测试设计工作台

更新：2026-10-22。

## 先区分三种东西

- 来源意图分类：从真实历史标签查找对话，例如信息查询、故障维修。它是分类目录，不是对话测试树。
- 对话测试树：共享用户起点，在后续关键节点设计继续、纠错、换问题等分支；每轮有待检验的处理要求。
- 模型执行记录：模型实际运行后产生的答复、工具调用和 Trace。设计中的检查点不能冒充已经通过的结果。

## 现在怎样体验

1. 进入「结果大盘 → 对话测试」。旧的 `tab=intents` 链接保留，但默认内容已经改为多轮测试设计。
2. 先查看自建的设备排查示例：正常处理、换设备纠错、反复纠错压力测试三条路径，共享同一首问。示例不是客户真实记录。
3. 在左侧切换路径，或在某轮下方选择另一种用户走法。右侧按顺序展示用户消息、模型待答位和本轮检查点；不会预填模型答案。
4. 点击「编辑」修改分支名、类型、用户消息和检查点。共享节点修改会影响所有经过它的路径。点击「增加另一种走法」或「增加后续回合」，可以继续设计；单节点最多三个分支，单路径最多二十个用户回合。
5. 通过「从真实对话起步」搜索当前项目，选定来源会话并核对首问。确认后替换当前设计为一个真实起点，再自行增加衍生分支。来源会话和消息编号保留；人工回复不会输入待答位，也不冒充真实发生过的分支。
6. 展开「测试配比」调整目标。参考值正常60、异常30、压力10，不是行业硬标准。计划数量按最大余数分配成整数；实际路径数直接从树结构统计，不重复复制路径补足数量。
7. 人工检查匿名信息，勾选后点击「保存测试设计」。草稿按项目存储在当前浏览器，显示实际版本号；不会写入 API Key，不自动外发，不同步服务器。清理浏览器数据会丢失草稿。
8. 原来的真实案例浏览移动到下方「来源意图分类」。来源数量与学习资格仍分别展示，不伪装成新增测试路径数量。

## 明确未完成的部分

当前仅为测试集设计、分支预览和浏览器草稿管理。多轮模型执行器、自动根据模型结果选择后续分支、节点检查评分、两模型路径公平对比和多轮 Trace 尚未接入此模块。现有单轮评测继续保留，不能更换名称后冒充多轮测试。

下一步执行协议需要冻结树版本、分支选择规则、工具沙箱状态和检查标准；同一分支的后续轮次应使用该模型自己之前的答复，不能每轮偷换成历史人工答复。检查点必须能提供证据，缺少证据不能判定通过。不同分支独立上下文；压力测试需单独报告，不计入线上真实拦截率。

## 验证

- `tests/dialogue-test-tree.test.ts` 检查分支共享、上下文路径、配比整数分配、删除后代、循环/非法节点、隐私基础校验和本地存储。
- `tests/dialogue_test_tree_dom.cjs` 检查选择路径、编辑共享回合、添加/删除分支、保存恢复、来源引用、目标与实际数量分开以及不发起模型调用。
- 所有示例和测试构造都不得当成供应商实测或真实客户成功案例。
