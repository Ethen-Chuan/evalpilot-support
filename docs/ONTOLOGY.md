# 本体图谱

2026-11-05 PRD 更新：主入口现在默认进入可维护的「领域本体工作台」。七类实体、版本化规则、别名导入、真实本地工具调试与可选客服 Harness 接入，见 [PRD 落地与演示边界](ONTOLOGY_PRD.md)。下文保留旧教学图谱的说明；其中“运行只在页面保留”只适用于旧业务演示，新工作台运行已持久保存。

2026-11-05 界面更新：示例默认采用 SVG 业务对象卡片，真实语料大图仍用 D3 Canvas；目录按需展开，对象详情与业务指令在右侧切换。布局、交互、全站样式及验证限制见 [工作台界面升级](UI_WORKBENCH.md)。以下保留数据、规则及历史验证说明，不把历史画布行为当作新版视觉验收。

本机完整版的主导航入口是「本体图谱」，地址为 `#ontology`。项目详情的「查看本项目关系图谱」携带当前项目；客服模拟台也提供本体教学入口。公开静态体验版没有真实语料图谱接口。

## 两种数据来源，不混为一谈

### 真实语料关系

节点包含项目、八个标注概念、已有人工标签、完整对话案例。八个概念是客户意图、用户情绪、产品类别、故障域、工单类型、知识覆盖、关联系统、知识分类。

连接只表示有来源可核对的「标注维度」「属于概念」「人工标注」「来源项目」。标签来自有效人工提交，不是模型生成；缺失标签不补造，多值和标注分歧保留，分歧关系用虚线显示。节点详情可跳转到关联案例列表或完整对话，再返回该项目图谱。

这不是从客户原文自动抽取故障实体，也不将两个标签的共同出现解释成因果。完整对话仍在项目和对话知识库中，图谱接口不返回消息正文、图片或视频。

### 本体与语义演示

地址为 `#ontology?mode=example`。设备、型号、故障码、部件、症状、服务动作、工单构成独立的人工编写 Schema；同义叫法和约束也是可点击的节点。A-100、A-200、E102 与部件的关系均为虚构教学数据，不是厂商维修依据。

默认进入「客服决策演示」，不再先展示图谱。运行前不显示任何预填结果；用客户问题启动任务，依次检查归一上下文、检索候选、查询条件、知识读取、处理建议和输出证据。

## 从业务任务验证本体的作用

### 各层职责

| 层 | 当前实现 | 不承担什么 |
| --- | --- | --- |
| 本体定义 | 统一叫法，区分症状、型号、故障码和部件，限定关系范围 | 不直接提供维修答案，不把所有对象连成同一种关系 |
| 知识内容 | 四条独立登记、带版本的虚构知识，引用本体中的症状或限定型号的故障实体 | 图上有节点但知识缺失时，不能据此编写答案 |
| 流程约束 | 条件不足不调用查询；有候选仍不允许直接换件 | 不依赖提示词“建议遵守” |
| 图谱证据 | 从单步或完整结果定位本次用到的精确节点和关系 | 不为了连通效果补边，不高亮未执行的派单 |
| 固定验收 | 独立文件中的预期集合与实际执行结果逐项比较 | 不是六维 Rubric，也不是真实模型成绩 |

当前知识为启动异常核实、黑屏核实、A-100/E102 和 A-200/E102 四条。默认任务故意缺型号：先输出澄清，再通过「补充 A-100 并继续」重新检查并读取该型号知识。用户补充仅记录为声明，未核验真实设备身份；补充与原话冲突不会覆盖原话。找不到知识时转人工核实，不把本体当答案库。

### 对照怎么计算

同一问题使用同一知识源：

1. **标准词与代码字面候选**：标准词、型号或代码任一命中即纳入候选，不做型号过滤。
2. **增加词典归一的候选**：只增加已登记的症状别名匹配，其他条件相同。
3. **流程实际引用**：满足条件后按规范症状，或唯一型号与代码做结构化只读查询。

前两列是有意简化、可复现的检索候选池，不能说成普通 RAG 或模型一定产生的错误答复。规范词对照本来就能找到知识，不强造增益。这里能证明具体机制改变了哪些查询与动作，不能证明生产召回率、准确率、幻觉率或经营收益已经改善。

### 执行记录与验收

每次本机任务记录六个可观察业务阶段的输入、输出、状态、耗时与关联图元素：归一、候选对照、条件检查、知识读取、形成结果、结构核对。被阻止的查询记为 `skipped`，不会假装调用工具。记录不包含模型隐含思维，也不声称逐行审计了全部底层代码。运行编号、本体与知识的版本/内容指纹用于区分结果；只保留在当前页面，离开或刷新会丢失，不冒充持久审计日志。

验收集含 12 条预先编写的合成案例：口语归一、同义改写、规范词对照、A-100 范围、A-200 范围、缺型号、补充型号、未知代码、未知型号、来源冲突、症状边界、换件拦截。点击后才真正逐条执行，并检查：

- 实际知识编号集合与候选部件集合是否等于固定预期；
- 下一步动作和查询工具是否等于固定预期；
- 换件拦截状态与结构证据约束是否符合要求。

每行显示预期、实际及三组检查结果，允许带入该场景重跑。预期存储独立于执行逻辑，但仍是同一项目自编的回归验收，不称为独立真实测试集。修改预期会引起失败；不能以检查文案或总分自证正确。这组结果不会写入真实客户数据集，也不覆盖六维评分。

要判断真实收益，下一阶段需保持模型、知识源、工具、输入与推理设置一致，在经授权的同一真实标注集上开启/关闭本体，比较适用知识选择、缺信息澄清、越权动作与失败案例；当前未实现该生产实验，也未接入客服 Harness 的真实推理。

### 图谱仍可独立探索

点击「本体定义与图谱」进入原有逐级探索（直达地址 `#ontology?mode=example&view=graph`）。业务结果的「在图谱中核对这一步」只定位该步证据；「查看完整决策依据」定位完整结果。返回客服决策视图保留原结果，修改输入则清除旧结果和旧图谱证据。图谱全屏仍可退出后返回原任务。

## 图谱旁的业务操作台：定义可以改，效果可以再跑

示例图谱右侧默认打开「业务指令」，可切到「节点详情」。点击图谱节点后，指令台同步显示目标及说明。它是有限中文语法到登记函数的本机分派器，不是大模型自由理解，也不是可以执行 Python、Shell 或任意代码的终端。帮助区列出支持格式，点击只带入文本，不自动执行。

### 一个能现场验证的交互

1. 发送 `运行客服任务“我的主机启动没反应。”`：初始词典没有这个叫法，结果保留缺口，不套用固定答案。
2. 发送 `给“启动异常”添加别名“启动没反应”`：后台调用 `add_alias` 在副本中试算，显示元素/边的变更前后及固定验收结果，此时尚未改变图谱。
3. 点击「确认执行本次修改」：函数重新校验后实际提交到独立本机数据库，图谱新增别名节点及规范叫法关系。
4. 再运行第一句：使用刚保存的本体版本，查到启动异常的知识。可展开真实函数参数、六步业务输出，定位这次执行关系。
5. 发送 `撤销上次修改` 并确认：恢复上一个本体快照；再次运行第一句恢复原行为。撤销本身也留记录，不抹除操作历史。

不是只改前端节点名称：图谱接口、旧词典解析、客服决策任务与固定验收都读取同一份本机工作区定义。Schema 注入使用参数传递，不替换模块级全局变量，避免并发请求串用定义。

### 支持的函数与保护范围

| 指令 | 实际函数 | 效果 |
| --- | --- | --- |
| `查看关联元素` | `inspect_node` | 查询当前节点及实际相连关系 |
| `添加别名“新叫法”` / `移除别名“新叫法”` | `add_alias` / `remove_alias` | 修改当前规范实体的词典映射；同名冲突被拒绝 |
| `说明改为“新的匿名说明。”` | `update_description` | 修改当前实体说明，不自动修改知识内容或关系 |
| `新增部件“散热模组”` / `新增症状“间歇闪屏”` | `create_entity` | 新增独立标识的实体；没有知识就不补造答案 |
| `关联“散热模组”，关系“示例组成部件”` | `add_relation` | 从当前选中实体指向目标，按登记类型验证 |
| `移除关联“散热模组”，关系“示例组成部件”` | `remove_relation` | 删除精确的一条允许修改的关系 |
| `运行客服任务“匿名客户问题”` | `run_customer_task` | 按当前版本执行真实本机检索与约束检查 |
| `运行固定验收` | `verify_workspace` | 执行独立文件中的固定预期，不自动修改预期 |
| `撤销上次修改` | `undo_change` | 预览并恢复上次修改前快照，最多回退最近 50 次修改 |

例如新增部件后，先选中「整机」再关联它。部件/症状可新增；基础类、型号范围、规则、原始案例不能通过此接口改写。派生别名节点不能当成规范实体改说明，系统会要求重新选择，不偷偷改写别的对象。故障码与工单不支持普通别名改写。现象指向部件的非法候选边会被类型检查拒绝；给 A-100 增加另一候选如果改变固定验收的预期集合，会显示失败并拒绝保存，而不是把预期一起改成通过。

描述编辑不等于业务内容已经审核正确；固定验收也只覆盖已列案例。演示可以真实修改自己的本体，但不获得退款、派单、维修或真实客户数据的写权限。

### 事务、并发与记录

- 用户指令先经本机脱敏门禁。敏感输入不进入解析器、预览或历史；经扫描的有效指令、预览及被语法/结构拒绝的指令留本机记录。
- 预览随机编号绑定函数、参数、当前版本，10 分钟失效；确认只接受该编号和版本，不接受重新传入参数。切换选中节点或编辑指令清除待确认项。
- 真正保存前再次执行隐私、结构和固定验收检查。工作区快照、预览消费状态及成功记录在同一 SQLite 事务提交；失败不能只保存一半。多窗口竞争只允许一个当前版本成功；重复确认、过期预览、撤销后重放旧预览均被拒绝。
- 所有修改写入 `data/ontology-workbench.sqlite3`，已被 Git 忽略；源 `backend/ontology_schema.json`、真实语料和质检数据不变，不会自动推送 GitHub。刷新页面和重启服务后可恢复工作区与操作历史。
- 面板显示最近 20 条记录，完整记录保留在该本机数据库；最多 100 个实体、每实体 30 个别名、300 条显式关系。操作记录不是不可篡改审计签名，也不提供多人权限体系。
- 如果后续代码迭代改变基础 Schema 的内容指纹，保留原工作区并停止读写，要求先迁移；没有实现自动合并或静默覆盖。
- 客服决策页自身的普通运行仍只保留页面状态；通过指令台执行的任务返回值随本机操作记录保存，两者不混称。

「在图谱中解析」在本机运行受控词典匹配和规则检查：

- 主机、机子、机器归一到示例的「整机」，不等于识别出同一台物理设备。
- 故障码必须与唯一型号共同匹配；缺失或多个型号时不生成候选部件关联。
- 同样的 E102 在不同虚构型号下有不同候选关系。
- 未知代码保持未知；直接更换部件的建议被阻止。
- 黑屏、启动异常和无法上电是不同症状，不把现象直接当成根因。

解析后自动回到图谱并切换到「本次解析」，仅保留本次命中的元素和后端明确返回的关系，不因为两个节点被命中就补一条连接。图下显示定位数量，右侧同步展示每项规则及原因。点击「全部节点」可以放回完整本体中观察，点击「定位解析结果」再次聚焦；「编辑问题与建议」回到输入位置，修改输入会清除旧结果。查询中切换来源或修改问题会取消旧请求，不把过期结论显示在新问题上。

这是确定性词典演示，只有有限的否定词处理，不是完整自然语言理解、OWL 推理机或真实诊断。尚未接入客服 Harness 的生产检索、评分或业务工具；不能声称该图谱已经提高模型准确率或降低幻觉。

## 怎么操作

1. 默认「逐级展开」。真实语料从项目节点开始；每次点击沿实际关系展开一层，并保留此前路径。示例默认展示一段相连的业务链，不从互不连通的概念散点开始。下方始终显示当前可见节点与已加载总节点数。
2. 「全部节点」显示本项目已加载的所有节点和关系；可缩放观察整体结构。
3. 点击节点时，图上展开与右侧更新同时发生。右侧保留定义、来源、方向和可逐页查看的相连关系；示例额外展示“叫法 → 规范词 → 所属概念”及关系含义，不把同义、组成、候选和约束混为一谈。「局部关系」仍可单独查看一层或两层邻居。
4. 每次最多展开 24 个相连元素，优先概念，再展开案例，明确显示当前筛选下待展开数量；可重复点击继续。「收起此分支」保留其他路径仍连接的共享节点，循环不重复创建；「重新开始」清空展开历史和筛选。搜索不可见元素会增加一个探索起点，不清空其他分支。旧总览的“展开关联案例”仍每批最多 100 个。
5. 拖动节点会固定位置；拖动背景平移，滚轮缩放。暂停、适应画布、重新布局、布局松紧和类型/关系筛选可控制显示。
6. 点击图谱右上角带文字的「全屏展示」进入演示视图；原「适应画布」仍只调整缩放，不是全屏。优先请求浏览器全屏；内置浏览器不支持或拒绝时，自动使用铺满当前页面的全屏，并如实标明「页面全屏」。顶部「退出全屏」或 `Esc` 返回，保留选中节点、筛选、解析结果与拖动位置，按新尺寸适应画布。
7. 全屏隐藏左侧目录，已选元素或解析摘要保留在右侧。顶部可独立开关「元素目录」「元素与证据」；窄屏改为可切换的侧面板，避免挤压画布。背景页面暂停滚动和键盘访问；退出恢复原焦点和滚动设置。「编辑问题与建议」先退出全屏再定位输入框；离开图谱页面会清理全屏状态。
8. 选中画布后，`+` / `-` 缩放、方向键平移、`0` 适应画布；非全屏时 `Esc` 取消选择，全屏时优先退出且不清除选择。没有画布能力时仍可使用元素目录和来源链接。
9. 修改或重新导入标注后点击「刷新图谱」。刷新重新读取当前数据，失败显示错误，不拿旧结果充当最新结果。

搜索支持名称、已定义别名和案例编号。缩放限制为 8%–500%，文本自动避让、在图内显示不下时隐藏，完整名称仍可通过悬停和详情查看。支持单指拖动，不宣称实现双指缩放。

## 用业务链讲清本体，而不是只有散点

教学示例默认按“客户叫法 / 统一概念 / 型号与故障码 / 候选与约束 / 处理与记录”分层，用带名称和类型的节点卡片显示，箭头保留源数据的真实方向。紫色表示叫法归一，候选关系使用虚线；关系文字避让节点。小画布以可读字号优先，需要平移或缩放查看；可切换自由力导向布局，也可全屏展示。语义分层不使用力导向动画，仍支持点击展开、拖动和缩放。

三个入口均来自同一份 Schema，而不是额外编造的示意连线：

- **叫法如何归一**：主机、机子、机器归到整机，再通过可选型号与限定型号的故障码关系，连接候选部件、约束、复核及示例工单。
- **同码为何不同**：并排显示 A-100/E102 与 A-200/E102 的不同候选。“可选型号”不是已识别客户的型号；运行给定问题后才显示本次词典匹配结果。
- **哪些建议被拦截**：候选部件受规则限制，点击“运行词典与规则”实际执行本机检查，直接换件建议返回 blocked；不会创建工单或执行维修。

界面明确区分“人工定义的示例关系”与“本次执行结果”。本次解析仍只显示后端返回的精确边，不能为了连成漂亮路径而补造关系；型号缺失或代码未知时，链路允许中断，右侧说明中断原因。业务关系补齐了整机与可选型号，以及两个候选部件各自的专业复核和约束，但没有编造型号间共享诊断。

## 数据和安全边界

- 只接受已登记且 `scanStatus=passed` 的语料项目，沿用现有私有数据恢复流程，不创建第二份公开数据集。
- 图谱查询与演示不调用外部模型、不产生模型费用、不执行退款、派单、换件等业务动作。教学输入经过本机脱敏门禁。
- 节点和关系带来源类型。图谱版本摘要随实际节点或关系变化，不是审计签名。
- 每个项目最多加载 10,000 段对话。超过时明确显示已加载/总量与不完整提示，不称为全量图谱。
- 自动扫描未发现明确敏感项不保证绝对安全；截图或对外分享前仍要核对项目名、内部标签及任何可识别信息。面试建议使用虚构教学视图。
- 服务只监听本机回环地址，没有多用户鉴权，不能直接开放到公网。
